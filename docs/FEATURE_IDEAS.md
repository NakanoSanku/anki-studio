# Anki Studio 功能规划与头脑风暴 (Feature Ideas & Roadmap)

本文档归纳整理了 Anki Studio 的潜在演进方向、功能构想与头脑风暴方案。所有设计均遵循项目核心哲学与架构边界：**本地优先（Local-first）**、**先审核再发布（Review Gate）**、**FSRS 科学排期** 以及 **对用户数据的零绑定与强主权**。

---

## 一、 产品原则与设计边界

在引入任何新功能时，应始终对齐以下设计约束（参考 [CONTEXT.md](file:///D:/UserData/Documents/Codes/anki-studio/CONTEXT.md)）：

1. **本机数据唯一真实源（Single Source of Truth）**：
   - 笔记、卡包与学习进度首先保存在本机的 IndexedDB 中；云同步与导出均属外围通道，不能削弱离线可用性。
2. **审核门控（Review Gate）**：
   - 所有新建、AI 批量生成、AI 补全或外部同步修改的笔记，默认进入「未审」状态。未审笔记不能进入「学习会话」、Voice Tutor 或导出。
3. **严格统一术语体系**：
   - 严格使用 **卡包**（非牌组/书库）、**笔记**（非条目）、**卡片**（模板渲染后的正反面）、**学习**（非复习）、**未审**（非新卡）、**模板**、**会话** 等术语。
4. **克制精简的交互外壳**：
   - 日常高频操作集中在「学习」与「笔记」，低频工具留在「设置」，保证极速、沉浸且符合直觉的移动端/桌面端统一手感。

## 三、 详细功能构想

### 1. 核心复习与会话体验 (Study & Recall UX)

#### 1.1 撤销误触评级 (Undo Last Rating)
- **背景痛点**：在连续快速刷卡过程中，极易误触评级按钮（如误点 `Easy` 或 `Again`），目前一旦评分立即持久化并跳到下一张，无法撤销。
- **设计思路**：
  - 在学习会话内部维护一个容量为 5~10 步的内存撤销栈（包含评级前的 FSRS card 状态、log 记录、学习队列位置与 completed 计数）。
  - 会话顶栏或悬浮按钮提供「撤销」操作，并支持快捷键 `Ctrl+Z` / `Cmd+Z`。
  - 触发撤销时，恢复上一步的卡片背面，用户可重新评估并提交正确评级。

#### 1.2 学习热力图与记忆健康大盘 (Study Heatmap & Retention Analytics)
- **背景痛点**：当前仅展示今日学习量与连续打卡天数（Streak），缺少长期直观的正反馈与记忆曲线洞察。
- **设计思路**：
  - **GitHub 风格打卡热力图**：统计历史每日复习卡片数，呈现学习节奏与年度复习分布。
  - **FSRS 状态透视**：
    - **稳定度（Stability）分布**：直观展示多少笔记已沉淀为长期记忆（如稳定度 > 100 天），多少仍在短期学习阶段。
    - **难度（Difficulty）散点图**：识别当前卡包整体认知负荷。
  - **未来复习负荷预测（Forecast）**：根据现有调度预测未来 7/14/30 天每日到期量，帮助用户合理控制每日新笔记引入节奏。

#### 1.3 考前冲刺 / 临时过滤学习 (Cram / Custom Study Session)
- **背景痛点**：面临考试、面试或专题复习时，用户希望集中复习某批特定笔记，但不想打乱正常的长期 FSRS 间隔排期。
- **设计思路**：
  - 允许在「学习」入口选择「临时冲刺」：可按标签、未熟练程度（如多次 Lapse 的卡片）或指定范围创建独立会话。
  - 提供选项：「纯浏览练习（不改变 FSRS 调度状态）」或「计入短期重新巩固」。

#### 1.4 手势与键盘交互增强 (Gestures & Shortcuts)
- **移动端沉浸滑卡**：翻面后支持全手势盲评（左滑 Again、下滑 Hard、右滑 Good、上滑 Easy）。
- **音频重播快捷键**：桌面端支持按 `R` 键快速重播当前正面/背面的 TTS 音频，无需鼠标点击微小播放按钮。

## 二、 内容创作与输入效率 (Card Creation & Ingestion)

#### 2.1 标签与分类系统 (Tags & Taxonomy)
- **背景痛点**：当前笔记仅包含文本字段，缺乏多维分类方式，随着卡包笔记量增长（>500 条），检索与管理成本显著上升。
- **设计思路**：
  - 在 `Card` 数据结构中引入可选的 `tags: string[]`。
  - 笔记列表支持按标签多选与层级筛选（如 `考试/GRE`、`词性/动词`）。
  - AI 批量生成时支持自动或手动指定附加标签；导出 APKG 时兼容原生 Anki Tag。

#### 2.2 一键查词速记建卡 (Instant Dictionary Lookup)
- **背景痛点**：AI 批量生成适合处理长篇材料，但若日常阅读遇到单个生词，手动输入释义和例句或等待 LLM 较慢。
- **设计思路**：
  - 笔记编辑器顶栏提供「查词速记」快速通道。
  - 输入单词后，通过轻量字典或本地词库毫秒级返回：音标、词频星级、常用释义与标准双语例句。
  - 点击「生成」，自动对齐当前卡包字段并落库为「未审」笔记。

#### 2.3 多模态制卡：OCR 拍照 / 截图 / PDF 导入 (Multimodal Ingestion)
- **背景痛点**：用户阅读纸质原版书、论文或教材时，存在大量拍照或选段制卡需求。
- **设计思路**：
  - 支持拖入 PDF/EPUB 章节，或上传教材拍照照片/网页截屏。
  - 调用多模态模型（如 Gemini 2.5/3.x Flash），指定 Prompt 自动提炼核心词汇、上下文原句及中文考点。
  - 提取结果直接填充至字段并存为待审笔记，附带原书出处字段。

#### 2.4 多媒体图片与音频字段支持 (Media & Images)
- **背景痛点**：医学、艺术、地理、生物及视觉词汇学习严重依赖图片。
- **设计思路**：
  - 字段支持粘贴剪贴板图片或拖入图像。
  - 底层使用 IndexedDB Blob / OPFS（Origin Private File System）管理媒体资源，保证完全离线可用。
  - APKG 导出引擎扩充支持：将引用的媒体文件打包进 APKG 的 `media` 归档。

#### 2.5 扩展 TTS 语种与离线发音 (TTS Language Expansion & Offline Fallback)
- **背景痛点**：目前 `TtsLang` 仅支持英语 `en` 与泰语 `th`，且依赖网络 TTS API。
- **设计思路**：
  - 扩展语言定义：增加 `ja` (日)、`ko` (韩)、`fr` (法)、`de` (德)、`es` (西)、`zh` (中) 等。
  - 增加无网络环境下的 Fallback：当离线或未配置 TTS API 时，平滑降级至浏览器原生 `window.speechSynthesis`。

## 三、 审核工作流提效 (Review Gate Workflow)

#### 3.1 批量多选审核与管理 (Batch Operations)
- **背景痛点**：AI 批量生成 30~50 条笔记后，逐个检查点击「通过」效率较低。
- **设计思路**：
  - 笔记列表支持「进入多选模式」：提供全选、按未审筛选、区间连选。
  - 底部浮动工具条支持：**一键审核通过所选**、**批量打标签**、**批量删除**、**批量针对空白字段触发 AI 补全**。

#### 3.2 重复与近义词检测 (Duplicate Detection)
- **背景痛点**：长期制作卡包时容易录入重复或词义完全重叠的词条。
- **设计思路**：
  - 在录入关键字或 AI 批量生成前，检测首字段（Key field）是否在当前卡包或全局已存在。
  - 发现同名卡时给出柔性警告并高亮原有笔记链接，支持合并或查看已有笔记。

#### 3.3 变更对比视图 (Diff View)
- **背景痛点**：从 Google Sheets 外部编辑同步回来，或点击 AI 补全后，用户很难在几秒内看清哪些内容发生了修改。
- **设计思路**：
  - 审核界面提供前后对比（绿色高亮新增内容、红色高亮替换前内容），提升审核安全感。

## 四、 AI 深度认知与互动辅导 (Cognitive AI Superpowers)

#### 4.1 难缠笔记 AI 诊断与助记生成 (Leech Card Diagnostic & Mnemonics)
- **背景痛点**：在 FSRS 算法中，某些难词用户可能遗忘次数（`lapses`）达到 4~6 次以上（Leech），单纯重复看背面很难攻克。
- **设计思路**：
  - 系统根据 FSRS 调度数据自动识别高遗忘率卡片，提供「AI 诊断」功能：
    1. **原因分析**：分析是否正面信息线索太弱、例句过于生僻、或与其它近义词产生混淆。
    2. **生成助记口诀（Mnemonic）**：自动生成词根词缀图解、谐音联想或生动的场景画面。
    3. **卡片微拆解建议**：自动建议拆分为 2 张更细粒度的原子卡片。

#### 4.2 主动回忆：翻面造句测评 (Interactive Sentence Production Quiz)
- **背景痛点**：看背面属于“被动识别”，许多学习者需要“主动运用”才能真正掌握输出能力。
- **设计思路**：
  - 会话翻面时，提供可选的输入框「造句自测」。
  - 用户用该词造句后提交，AI 在 1~2 秒内给出语法批改、地道表达建议与搭配点评。

#### 4.3 卡片内轻量上下文问答 (Inline Context Q&A)
- **背景痛点**：现有的 Gemini Live 是全屏沉浸语音模式，有时用户只是在翻面时对某句例句的介词搭配或文化背景有一两句疑问。
- **设计思路**：
  - 学习翻面后提供一个小气泡「问问 AI」，滑出半屏轻量抽屉，支持纯文本追问，解答完毕关闭后立即无缝继续当前学习会话。

## 五、 数据同步与生态扩展 (Sync & Ecosystem)

#### 5.1 开放式云同步后端 (WebDAV / GitHub / S3)
- **背景痛点**：当前云同步与 Google Sheets 深度绑定，部分用户可能更青睐私有云存储（如坚果云 WebDAV、GitHub Gist、自建 MinIO）。
- **设计思路**：
  - 将同步协议抽象为 `SyncProvider` 接口，支持可插拔扩展：
    - `GoogleSheetsProvider` (现有)
    - `WebDavProvider` (增量加密 JSON 同步)
    - `GitHubProvider` (基于 Git commit 的仓库同步)

#### 5.2 精品模板社区与预设卡包分享 (Template Hub & Preset Decks)
- **背景痛点**：很多初学者不熟悉 HTML/CSS，难以自行设计出赏心悦目的卡片模板。
- **设计思路**：
  - 在卡包设计页面内置「模板广场」：
    - 极简排版风 (Notion / Apple 风格)
    - 双语杂志风 (Magazine / Editorial)
    - 医学药理填空模板 (Cloze / Clinical)
    - 日韩语平假名/音调高亮模板
  - 支持一键导入模板并自动映射字段。

## 六、 阶段演进路线建议 (Phased Roadmap)

```text
Phase 1: 学习与复习闭环体验 (Quick Wins)
├── 学习会话撤销评分 (Undo Last Rating)
├── 键盘音频快捷键 (R 键重播) 与移动端滑动交互
├── 学习打卡热力图与 FSRS 记忆大盘可视化
└── TTS 语种扩充 (日/法/德/西等) 与 Web Speech Fallback

Phase 2: 组织与生产力提效 (Scalability)
├── 笔记标签系统 (Tags) 与多维筛选
├── 批量多选审核 (Batch Approve) 与批量操作
├── 一键查词速记建卡 (Instant Dictionary Lookup)
└── 重复笔记与冲突检测

Phase 3: 认知增强与生态打通 (Superpowers)
├── 顽固难词 (Leech) AI 助记生成与拆解诊断
├── 翻面轻量上下文追问与造句测评
├── 多模态截图 / PDF 制卡导入
└── WebDAV 开放式同步协议扩展
```
